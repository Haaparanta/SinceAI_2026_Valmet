## 1. What Valmet asks for (brief §02, §06, §07)

A demonstrator that:

1. **Extracts and 3D-frames as many assets as possible** from `Industrial Boiler Room.ply` (a 3D Gaussian Splatting scan), in the spirit of the two reference videos ("Every object, its own asset", indoor mesh / bounding-frame tagging).
2. **Maps the xlsx metadata** (statuses, telemetry, docs) onto the extracted objects. Random or procedural mapping is explicitly allowed; one object is the pre-determined **faulty target**.
3. **Simulates an avatar or robot** walking an automatically computed, **collision-free, realistic route** to the faulty device (no walking through walls, boilers or piping).
4. **Highlights nearby assets** with 3D frames and their mapped metadata as the avatar moves.
5. **Triggers an AI diagnosis** grounded in the xlsx data and docs at the target.

### Judging weights (brief §06)

| # | Criterion | Weight |
|---|---|---|
| c1 | Semantic asset extraction density & 3D framing | **30 %** |
| c2 | Realistic obstacle-aware navigation & proximity display | **25 %** |
| c3 | AI diagnostics, grounding & explainability | **20 %** |
| c4 | Backend architecture & technical implementation | 15 % |
| c5 | Demo clarity & innovation | 10 % |

The brief prefers backend intelligence over UI polish: "a lightweight visualization … is strongly preferred over a polished mobile app with weak spatial processing."

### Submission (brief §07)

Runnable demo, repo with README and setup, 5–8 slides, video ≤ 5 min, and a short technical note (models, libraries, components).

### Suggested approaches named in the brief (§04)

Point-cloud and splat segmentation, clustering, **SAM/CLIP lifted to 3D**, geometric heuristics; occupancy grids, voxel traversal, NavMesh, A*, RRT*; proximity queries; RAG copilot; visualizers like Rerun, Open3D, Viser, PyVista, Three.js, Unity, Unreal, Omniverse/OpenUSD.

## 4. Locked design: wedge D "Approve-to-Build Twin"

The user's five non-negotiables:

1. Objects are identified **one by one** and added to the central scene only on **human approval**.
2. That approval happens in a **web interface**.
3. **Model work runs offline**: a batch pipeline does the heavy lifting, the browser only reviews and renders, and the demo must survive with Wi-Fi off.
4. **After every addition, a snapshot**: the new object in **red**, everything else **see-through grey**.
5. The judges' demo is **walkable in three.js on the web**, with **Meta Quest 3 (WebXR)** as a stretch goal.

Planned pipeline (from the PM pack): `01_clean` → `02_floor_grid` → `03_propose` → `04_mesh` → `05_bind_metadata` → `06_route` → `07_demo_cache`, a FastAPI service, and a Vite + TypeScript + three.js web app with `/curate` (curator) and `/` (twin).

### Local machine

**Apple M1, 8 GB RAM** (measured by the 02 research agent): run one model at a time, prefer ≤ 4B models live, torch MPS works, Ollama is not installed yet. Homebrew Python 3.15 without numpy or open3d, so use **`uv` with Python 3.12**. Pin **`open3d==0.19.0`**: 0.20.0 fails to import without Homebrew `libusb`. `node`, `cargo` and `uv` are available. No `ffmpeg`, no `pandoc`. A GPU is not confirmed for the team.

## 7. Conflicts and open items across the notes

1. **Model size vs. this laptop.** Note 05 recommends `qwen3.5:9b` for a 16 GB Mac, but the measured machine is an **M1 with 8 GB**. On this laptop use the **4B** (or smaller) model, one model at a time with `keep_alive: 0`, or run the batch on a teammate's larger Mac. The cached answers in `data/cache/` mean the demo itself doesn't need a model at all.
2. **Metric scale is still unknown.** Floor-to-ceiling is 1.97 units, which suggests 1 unit ≈ 1.5–3 m. Notes 03 and 04 use "units as metres" for cell size, agent radius, eye height and walk speed. Calibrate one `METRES_PER_UNIT` from a door or pipe and apply it everywhere.
3. **Tooling to install before Wi-Fi goes off:** Ollama + model weights, `brew install libusb` (or pin open3d 0.19.0), `ffmpeg`, the troika font and the npm packages.
4. **Data gaps in the pack:** `DOC-ASSET-017.md` and the 14-day telemetry CSV are referenced but not shipped (note 05). Ask Valmet in Discord.
5. **Theme vs. snapshot colours.** Red/grey is used only in snapshots, so it doesn't clash with the Cyberpunk status tokens (note 04).
